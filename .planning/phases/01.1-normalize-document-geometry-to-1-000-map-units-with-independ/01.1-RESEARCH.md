## User Constraints (from CONTEXT.md)

### Locked Decisions

### Document coordinates
- [D-01] Map geometry has top-left origin, x right, y down, double-precision CPU coordinates, exactly 1,000 units on its longest edge and aspect-scaled shorter edge.
- [D-02] Initial grid counts establish aspect ratio and starting Grid only; later grid spacing does not resize map geometry. Grid UI remains Phase 4.
- [D-03] Imported raster pixel dimensions establish aspect and initial editing sampling, not map extents. Keep source dimensions/provenance and an explicit source-to-map transform.

### Independent resolution and units
- [D-04] Editing resolution is fixed at creation/import in P0; export resolution is independent. Longest-edge preset contracts are 1K/2K/3K/4K editing and 1K/2K/3K/4K/8K/16K export, K = 1,024 pixels. Preset selection UI and advanced export controls remain Phase 4.
- [D-05] Brush diameters, river geometry and future map-relative sizes use map units. UI handles/markers stay in screen pixels. Zoom or output resolution cannot change committed geometric sizes.

### Compatibility and preservation
- [D-06] Existing Phase 1 pixel-space project data must not be silently reinterpreted. Test migration or explicit safe legacy handling, including retained editable commands and reopen/history behavior.
- [D-07] Preserve fixed Background/Foreground terrain, single Foreground mask, river semantics, bounded rendering, export cancellation/atomic publication and Phase 1 durability.

### Acceptance examples
- [D-08] A 4:3 map is 1,000 × 750 units for both 40 × 30 and 80 × 60 initial grids and for 1K or 4K editing sampling.
- [D-09] A 7,559 × 8,192 imported raster maps to 922.7294921875 × 1,000 units with no preview stretch.
- [D-10] A 96-map-unit brush retains the same relative map size and placement at 1K and 4K output; automated tests cover import, gestures, persistence/history and viewport/export alignment.

### the agent's Discretion
- Internal type and schema design, migration mechanism, test fixture design, and whether existing projects migrate eagerly or on first open, provided D-06 is satisfied.

### Deferred Ideas (OUT OF SCOPE)

Phase 4 owns editing/export preset selectors, the Grid UI, DPI and advanced output settings. Phase 2/3 own stamps, paths and labels, but must consume the normalized map-unit contract from this phase.

## Summary

The domain already uses double `MapPoint` coordinates and `double Width`/`Height`, and `DocumentRasterTransform` converts between document and output pixels. The missing contract is the meaning of those dimensions: `ImportProject` and `Main.CreateFlattenedSnapshot` currently copy imported scene width/height directly into `MapProject`, while `MapCanvas` sizes editing tiles from preview dimensions. [VERIFIED: src/Mapwright.Domain/MapModel.cs:899-909] [VERIFIED: src/Mapwright.Domain/Geometry.cs:48-92] [VERIFIED: src/Mapwright.Application/ImportProject.cs:255-259] [VERIFIED: Scripts/App/Main.cs:598-615] [VERIFIED: Scripts/App/MapCanvas.cs:220-245]

The renderer evaluates strokes in document coordinates, so a single uniform conversion from old/source coordinates into a 1,000-unit longest-edge system preserves aspect and relative placement. The export adapter currently calls `graph.Evaluate(snapshot)` at preview resolution and nearest-neighbor scales that frozen frame to the requested PNG dimensions; this does not independently sample editable geometry at 1K and 4K. Preserve the bounded tile writer and atomic publication, but make its frozen tile capture evaluate the same immutable project revision at target pixel centers. [VERIFIED: Scripts/Rendering/ConnectedTerrainGraph.cs:566-646] [VERIFIED: Scripts/Export/DocumentPngExport.cs:840-905] [VERIFIED: Scripts/Export/DocumentPngExport.cs:612-660] [VERIFIED: Scripts/Export/DocumentPngExport.cs:810-815]

**Primary recommendation:** Add one explicit map-unit geometry and raster-sampling contract, route both import paths and the viewport/export through it, then migrate legacy SQLite histories transactionally with a safe refusal if any retained command cannot be converted. [CITED: .planning/phases/01.1-normalize-document-geometry-to-1-000-map-units-with-independ/01.1-CONTEXT.md D-01–D-10]

## Architecture Patterns

### Data flow

```text
new grid counts or .ink source dimensions
                 ↓
validate aspect and choose map geometry (longest edge = 1,000)
                 ↓
persist immutable geometry + editing pixel size + source-to-map transform
                 ↓
pointer pixels ─→ map-unit commands ─→ SQLite revision/history
                                      ↓
                            frozen renderer snapshot
                             ↙               ↘
                 editing/viewport pixels   export tile pixels
                             ↘               ↙
                       same map-unit geometry
```

This flow is the implementation recommendation implied by the locked separation of geometry and sampling. [CITED: .planning/phases/01.1-normalize-document-geometry-to-1-000-map-units-with-independ/01.1-CONTEXT.md D-01–D-05]

### Pattern 1: Uniform source-to-map conversion

For positive source width `W` and height `H`, recommend `s = 1000d / Math.Max(W,H)`, `mapWidth = W*s`, `mapHeight = H*s`. Transform every source-space point, offset, radius, width and effect distance by **the same scalar** `s`; preserve the source pixel dimensions separately. For `W = 7,559`, `H = 8,192`, this yields the locked `922.7294921875 × 1,000`. The current `ImportedRasterTransform` has literal fields `OffsetX`, `OffsetY`, `ScaleX`, `ScaleY`; retain explicit per-raster transforms and compose them with the source-to-map transform, including nonzero offsets. [CITED: .planning/phases/01.1-normalize-document-geometry-to-1-000-map-units-with-independ/01.1-CONTEXT.md D-09] [VERIFIED: src/Mapwright.Domain/MapModel.cs:53-65]

Keep the imported scene dimensions and raster intrinsic dimensions/provenance in separate fields. The current parser reads `normSceneSize` into `MapDocument.Width`/`Height` and creates each raster transform as scene-width/raster-width; the new boundary must convert that transform exactly once. Both `ImportProject.ExecuteAsync` and `Main.CreateFlattenedSnapshot` need this shared conversion; otherwise the two recovery modes diverge. [VERIFIED: Scripts/Core/InkImportService.cs:139-152] [VERIFIED: Scripts/Core/InkImportService.cs:72-83] [VERIFIED: src/Mapwright.Application/ImportProject.cs:255-259] [VERIFIED: Scripts/App/Main.cs:598-615]

The real `.ink` path distinguishes `normSceneSize` from cached raster `Width`/`Height`; preserve that distinction in tests. A downsampled terrain checkpoint must inherit the full scene aspect and transform rather than redefine the map from its cache size. [VERIFIED: Scripts/Core/InkImportService.cs:139-152] [VERIFIED: Scripts/Core/InkImportService.cs:185-203]

### Pattern 2: Independent pixel sampling

Persist editing pixel width/height or a longest-edge preset with derived shorter edge, in addition to map-unit geometry. Compute output pixel dimensions from the chosen longest-edge count and document aspect, rounding the shorter axis once using an explicit policy. `DocumentRasterTransform` already maps pixel centers into document coordinates with the literal formula `(outputX + 0.5) * DocumentWidth / OutputWidth` and its Y counterpart; make this shared transform authoritative for viewport, invalidation and export. [VERIFIED: src/Mapwright.Domain/Geometry.cs:48-92] [CITED: .planning/phases/01.1-normalize-document-geometry-to-1-000-map-units-with-independ/01.1-CONTEXT.md D-04]

**Resolved import sampling policy:** Select the nearest supported longest-edge editing count from the exact list `1024, 2048, 3072, 4096`; ties select the larger count, and sources above `4096` select `4096`. Derive the shorter editing pixel edge from the normalized map aspect using midpoint-to-even rounding. Retain source scene and raster intrinsic dimensions/hashes independently; preview/cache dimensions never set the map extent. This is the chosen implementation policy under D-03/D-04 discretion, recorded verbatim in Plan 01's `assumptions_and_boundaries`: “choose the nearest supported longest-edge editing count among 1024, 2048, 3072, 4096; ties round upward and sources beyond 4096 cap at 4096.” No preset selector UI belongs in this phase. [VERIFIED: .planning/phases/01.1-normalize-document-geometry-to-1-000-map-units-with-independ/01.1-01-PLAN.md:49-50] [VERIFIED: .planning/phases/01.1-normalize-document-geometry-to-1-000-map-units-with-independ/01.1-01-PLAN.md:72-82] [CITED: .planning/phases/01.1-normalize-document-geometry-to-1-000-map-units-with-independ/01.1-CONTEXT.md D-03–D-04]

### Pattern 3: Target-scale editable rendering, source-scale raster resampling

The existing graph maps output pixels into `snapshot.Width`/`Height` and tests stroke/land/river geometry at those positions. Reuse that evaluation in a frozen tile renderer at the requested target dimensions. Imported bases may be resampled from immutable intrinsic rasters; editable commands must be re-evaluated at target pixel centers. Do not allocate a whole 16K decoded canvas: `EvaluateRegionAtSize` currently calls `GetInputs` that allocates canvas-sized decoded arrays, so a direct 16K call would defeat the export buffer contract. Refactor raster sampling to tile/strip scoped or another bounded source cache before switching the export adapter. [VERIFIED: Scripts/Rendering/ConnectedTerrainGraph.cs:115-146] [VERIFIED: Scripts/Rendering/ConnectedTerrainGraph.cs:188-256] [VERIFIED: Scripts/Rendering/ConnectedTerrainGraph.cs:611-646] [VERIFIED: Scripts/Export/DocumentPngExport.cs:652-705]

### Pattern 4: Versioned, all-or-nothing legacy migration

`MapProject` currently defaults to `StorageFormatVersion = 2`, `ValidateConnectedTerrain` requires version `2`, and SQLite creates `schema_info(version) = 2`; the snapshot and schema versions are checked for equality on load. Quote the present values exactly: `StorageFormatVersion = 2`, `StorageFormatVersion != 2`, `VALUES (2)`. [VERIFIED: src/Mapwright.Domain/MapModel.cs:899-909] [VERIFIED: src/Mapwright.Domain/MapModel.cs:949-952] [VERIFIED: src/Mapwright.Infrastructure/SqliteProjectRepository.cs:645-653] [VERIFIED: src/Mapwright.Infrastructure/SqliteProjectRepository.cs:1094-1106]

Recommend a distinct normalized format version and an open-time migration gate that first identifies v2 before any new interpretation. Convert the authoritative baseline snapshot, all retained command payloads (including redo branch), any authoritative full snapshots and source-to-map metadata with the same scalar. Rebuild or discard only *derived* history/renderer caches; preserve command IDs, revisions, cursor and blob hashes. Commit schema/version and rewritten authoritative data atomically, validate replay at cursor and latest revision, and retain a recoverable pre-migration copy until validation succeeds. If an unsupported payload, invalid scale, range violation or filesystem failure prevents exact conversion, leave the original untouched and return an actionable legacy result. This is a recommended migration mechanism, not an observed current feature. [VERIFIED: src/Mapwright.Infrastructure/SqliteProjectRepository.cs:645-713] [VERIFIED: src/Mapwright.Infrastructure/SqliteProjectRepository.cs:909-960] [VERIFIED: src/Mapwright.Infrastructure/SqliteProjectRepository.cs:230-265] [CITED: .planning/phases/01.1-normalize-document-geometry-to-1-000-map-units-with-independ/01.1-CONTEXT.md D-06]

This is preferable to leaving normal editing in v2 pixel space because future stamps and labels need one map-unit contract. The authorized alternative is explicit safe legacy handling, including refusal with a recoverable original when exact conversion is impossible; it must be selected visibly on open and covered by reopen/history tests. [CITED: .planning/phases/01.1-normalize-document-geometry-to-1-000-map-units-with-independ/01.1-CONTEXT.md D-05–D-06]

The migrator must cover legacy and resolved texture strokes (sample positions, radius, jitter offsets, anchors), Land strokes, river points and widths, coastline/effect distances, bounds embedded in history deltas, and import raster offsets/scales. Brush spacing, softness, opacity, rotation and RNG/recipe versions are dimensionless and should retain their original values. The stroke and river records expose the relevant geometry in the domain; command types are explicitly deserialized in the repository. [VERIFIED: src/Mapwright.Domain/MapModel.cs:182-202] [VERIFIED: src/Mapwright.Domain/MapModel.cs:237-256] [VERIFIED: src/Mapwright.Domain/MapModel.cs:394-408] [VERIFIED: src/Mapwright.Domain/MapModel.cs:511-520] [VERIFIED: src/Mapwright.Domain/MapModel.cs:795-805] [VERIFIED: src/Mapwright.Infrastructure/SqliteProjectRepository.cs:935-956]

**Resolved legacy value policy:** Multiplying old pixel diameters/widths by `1000/max(W,H)` can put them below current normalized limits. For this phase, refuse migration of any converted brush or river value outside the normalized validators; do not clamp, round up, drop a command or reinterpret the original. Leave the original format-2 project untouched, return a typed actionable refusal, and do not bind an edit session to a partial sibling. Migratable values use the sibling-copy path and must preserve baseline, cursor and redo. This is the conservative explicit-safe-handling branch authorized by D-06. The present lower limits are quoted exactly: texture `MinimumDiameter = 1`, Land `MinimumDiameter = 1`, river `MinimumWidth = 1`. ## Common Pitfalls

1. **Only changing `MapProject.Width`/`Height`:** Import transforms, legacy commands, brush radii, river widths and viewport mapping would retain old units and visually shift. Test both import entry paths and every command family. [VERIFIED: src/Mapwright.Application/ImportProject.cs:255-259] [VERIFIED: Scripts/App/Main.cs:598-615] [VERIFIED: Scripts/App/MapCanvas.cs:848-859]
2. **Using preview pixels as geometry or editing policy:** `MapCanvas` presently sizes tiles from `PreviewWidth`/`PreviewHeight`, and `ConnectedTerrainGraph.Evaluate` defaults to the preview size. New documents need a persisted editing sampling independent of source and export. [VERIFIED: Scripts/App/MapCanvas.cs:220-245] [VERIFIED: Scripts/Rendering/ConnectedTerrainGraph.cs:99-113]
3. **Stretching imported bases:** Current `GetInputs` resamples by entire source width/height to canvas width/height, without consulting each raster's stored transform. If a raster has an offset or partial extent, a naive normalization can stretch it over the full map. Verify transform placement and clipping; unverified structured mapping must degrade to the preserved visual fallback. [VERIFIED: Scripts/Rendering/ConnectedTerrainGraph.cs:220-256] [VERIFIED: src/Mapwright.Application/ImportProject.cs:300-332]
4. **Exporting a scaled viewport frame:** `GraphFrozenRenderer` currently nearest-neighbor scales `graph.Evaluate(snapshot)`; a 96-unit stroke's committed geometry remains the same but edge quality at 4K would be inherited from the lower-resolution frame. Target-scale editable evaluation must stay bounded. [VERIFIED: Scripts/Export/DocumentPngExport.cs:840-905]
5. **Assuming schema version equals coordinate version automatically:** Current loader checks `schema_info.version` against project `StorageFormatVersion`, while history reconstruction can choose cached checkpoints. Change the format contract coherently, invalidate old checkpoints and verify redo/cursor after restart. [VERIFIED: src/Mapwright.Infrastructure/SqliteProjectRepository.cs:1094-1106] [VERIFIED: src/Mapwright.Infrastructure/SqliteProjectRepository.cs:860-890] [VERIFIED: src/Mapwright.Application/HistorySession.cs:185-235]
6. **Large target allocations:** The existing full-frame input cache is proportional to output canvas pixels; avoid invoking it at 16K before tiling inputs. Keep the measured Phase 1 resource and seam gates. [VERIFIED: Scripts/Rendering/ConnectedTerrainGraph.cs:115-130] [VERIFIED: Scripts/Rendering/ConnectedTerrainGraph.cs:245-256] [CITED: .planning/phases/01-connected-imported-terrain/01-VERIFICATION.md]
7. **Weak extent validation:** `ValidateConnectedTerrain` checks format and terrain identities but has no width/height invariant. Add finite, positive, 1,000-longest-edge validation for normalized projects while keeping legacy validation separate. [VERIFIED: src/Mapwright.Domain/MapModel.cs:949-971]
8. **Screen cue geometry:** The current brush cue computes its screen diameter from the X ratio only. At an integer-rounded non-square output size, test its relation to the mapped Y footprint and keep handle/marker dimensions screen-fixed. [VERIFIED: Scripts/App/MapCanvas.cs:619-638] [CITED: .planning/phases/01.1-normalize-document-geometry-to-1-000-map-units-with-independ/01.1-CONTEXT.md D-05]
